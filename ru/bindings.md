# Разобраться с привязкой из старой конфигурации

Если после импорта поле больше не меняется вручную, проверьте, не получает ли оно значение из другого свойства. Bindings связывает источник и получателя внутри одного экземпляра EyeAuras. Основное руководство по текущему редактору — [Привязки](/ru/features/bindings); здесь — короткий путь проверки такой связи.

## Повторить связь на своём тексте

1. В своей активной ауре создайте два оверлея **Text**: Источник и Копия. У первого задайте **Content** равным `Готово`.
2. У **Content** второго нажмите индикатор привязки. В **Binding Editor** выберите ауру, оверлей Источник и его **Content**, затем **bind**.
3. Измените Content Источника на `Пауза`. Оба оверлея должны показать новый текст; обратного изменения источника при этом не возникает.
4. Для возврата к самостоятельному полю откройте контекстное меню индикатора получателя и выберите **Un-bind**. После этого задайте его собственный текст.

Это один и тот же механизм, который в старом описании открывался чёрным прямоугольником справа от поля. В текущей оболочке важны само поле и индикатор, а не его прежнее положение.

| Что проверить | Как понять связь |
| --- | --- |
| Источник | Объект и путь свойства, переменная или значение по умолчанию. Источник должен существовать. |
| Получатель | Свойство, у которого открыт Binding Editor. Направление связи идёт к нему. |
| Тип значения | Редактор предлагает совместимые значения и доступные преобразования; совпадение текста названий полей недостаточно. |
| Чёрный индикатор | Связи нет. |
| Цвет связанного индикатора | Зависит от типа связи: обычное свойство, переменная либо значение по умолчанию. Красный сигнализирует о неработающей связи. |
| Ошибка в редакторе | Прочитайте причину: удалённый объект и невозможное преобразование требуют разных исправлений. Автоматическое восстановление любой ссылки не обещается. |
| Bind to Default | Получение соответствующего [значения по умолчанию](/ru/features/default-properties). |

## Что можно переносить из прежних примеров

| Задача | Существенное условие |
| --- | --- |
| Общее окно нескольких триггеров | Связать их Target Window в правильном направлении либо использовать общую настройку папки. |
| Общая частота проверки | Получать Target FPS из одного источника или переменной. Цена всей схемы зависит и от работы самих триггеров. |
| Координаты результата поиска | Брать фактическую найденную область и согласовать экранные/оконные координаты с действием. Связь сама не выполняет клик. |
| Область поиска и положение оверлея | Проверить источник, получателя, систему координат и смещение; не рассчитывать на двустороннюю синхронизацию из одной связи. |
| Ползунок собственного UI | UI меняет явно переданную переменную или свойство, а привязка доставляет значение получателю. Обычный Razor не получает Script.csx globals автоматически. |
| Экспорт и импорт | Сохраняются настройки связей; в наборе должны быть нужные объекты. Произвольные строки кода и внешние ссылки не исправляются автоматически. |

Привязки используют наблюдение за изменениями и выражения, но не соединяют два независимых процесса или профиля. Условный выбор значения и преобразование требуют поддержанного контекста, а не названия ещё одной обещанной будущей функции.

Для найденной области смотрите [практический пример привязки](/ru/features/bindings) и [координаты](/ru/features/coordinate-system). [Dependencies Viewer](/ru/overlays/dependencies-viewer) показывает связи условий аур; считать его полным просмотрщиком всех привязок свойств нельзя.
