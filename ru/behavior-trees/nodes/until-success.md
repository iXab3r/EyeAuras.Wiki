# Until Success — повторять проверку до успеха

Если проверка пока не выполнена, а последовательность должна остаться на этом месте и попробовать снова при следующем тике, используйте `Until Success`. Один вызов узла делает одну попытку ребёнка. Внутреннего бесконечного цикла здесь нет.

## Дождаться изменения своего условия

Подготовьте отдельное дерево с `Activation → Is Loaded` и `Execution → When Activated → Do nothing`. Все результаты в этом опыте задаются через Fixed Status, без внешних действий.

1. Добавьте через `Add new Node` узлы и соедините их по схеме. Дети Sequence идут слева направо.
2. У ребёнка Until Success выберите `General → Status → Failure`, у двух остальных Fixed Status — `Success`. В настройках Until Success поле `General → Child` показывает подключённую проверку.

```text
My Tree
└─ Sequence
   ├─ Fixed Status: Success
   ├─ Until Success
   │  └─ Fixed Status: Failure
   └─ Fixed Status: Success
```

3. Нажмите верхнюю `Tick BT Once`. Первый шаг пройдёт; проверка вернёт Failure, а Until Success и Sequence — `Running`. Последний шаг ещё не выполнится.
4. Повторите тик без изменения проверки. Будет сделана ещё одна попытка ребёнка Until Success. Sequence продолжит с этого места, не повторяя свой первый шаг.
5. Смените у проверки Status на `Success` и снова нажмите кнопку. Until Success завершится с Success, Sequence выполнит последний шаг. Следующий тик после завершения начинает новый проход Sequence.

| Результат ребёнка | Результат Until Success |
| --- | --- |
| Success | Success — повтор больше не нужен в этом проходе |
| Failure | Running — новая попытка при следующем вызове |
| Running | Running — незавершённая работа продолжается при следующем вызове |

Собственных настроек числа попыток и паузы у Until Success нет. При автоматическом запуске частота зависит от [настроек дерева](/ru/behavior-trees/nodes/root) и длительности самого обхода. При ручном запуске каждую попытку вызывает читатель.

<details>
<summary>Что происходит с состоянием ребёнка</summary>

Until Success сам не сбрасывает ребёнка после Failure или Success. Дочерний узел продолжает жить по своему контракту: это важно для таймеров, составных узлов и скриптов с сохранённым продолжением. Структурный сброс дерева очищает принадлежащее ему состояние; очистка отображаемого статуса этого не делает. Отмена или ошибка ребёнка не превращаются автоматически в ещё одну обычную попытку.

</details>
