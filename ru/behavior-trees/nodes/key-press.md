# Key Press — перенести прежнюю настройку на текущий узел

Если вы пришли сюда из старого примера с `Key Press`, берите текущий шаблон с тем же именем. Всё про события, удержание и сочетания — на странице [Key Press](/ru/behavior-trees/nodes/KeyPress).

## Настроить адресата и проверить одну клавишу

Откройте отдельное окно локального текстового редактора с одной строкой черновика и поставьте каретку в середину строки. Проверять будем клавишей Home: каретка перейдёт в начало строки, и это видно без буфера обмена и отправки текста.

1. Положите дерево в отдельную папку. В её `Triggers/Actions/Overlays Defaults` включите `Target Window` и выберите окно черновика. Через `show more...` включите `Input Simulator → Windows Input`.
2. В дереве оставьте `Activation → Is Loaded`, `Execution → When Activated → Do nothing`. В `Settings` проверьте, что там не задана другая цель или другой механизм ввода. Значения наследуются от папки или задаются у самого дерева, подробнее — [свойства по умолчанию](/ru/features/default-properties).
3. Добавьте текущий `Key Press` через `Add new Node` и соедините со входом. Задайте `General → Keys = Home`, `Delay = 30 ms`, `Input → Press and release`.
4. В `Window` узла должно стоять именно окно черновика, в `Simulator` — Windows Input. Эти поля показывают, что узел унаследовал. Отдельно в узле их не выбирают.
5. Нажмите `Tick BT Once` один раз. Windows Input активирует редактор, каретка перейдёт в начало строки, узел вернёт Success. Если проверяете существующую схему, сначала повторите только этот один шаг в своей копии.

Как старые подписи называются сейчас:

| Прежняя настройка или задача | Текущий путь |
| --- | --- |
| Клавиша или сочетание | Key Press → General → Keys |
| Key Press Delay | General → Delay, постоянное значение или случайный диапазон |
| Input Type | General → Input: Press and release, Press and hold либо Release |
| Окно и симулятор из Folder Properties | Значения по умолчанию папки. Локальные Settings дерева могут их переопределить. Проверяйте итоговые Window / Simulator в узле |
| Длинная последовательность | Несколько Key Press в BT Sequence либо Run Aura с настроенным действием Send Sequence |

В последнем варианте готовый [Send Sequence](/ru/actions/sendinput/send-sequence) вызывается через [Run Aura](/ru/behavior-trees/nodes/execute-aura). Окно и ввод настройте у **исходного действия**: из дерева они в него сами не подставляются.

Выбранный Target Window не гарантирует работу в фоне. В примере Windows Input сам активирует окно, у других механизмов свои ограничения. Если в старой схеме было удержание, перенесите и отдельный Release: остановка между Down и Up его не заменяет.
