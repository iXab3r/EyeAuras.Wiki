# Selector — выбрать действие по приоритету

Нужно использовать умение, если оно готово, а иначе — выполнить обычную атаку. Selector перебирает варианты по порядку и выбирает первый, который выполнился успешно.

Проверку готовности умения вы настраиваете отдельно. Selector управляет выбором ветки, а не определяет состояние игры.

Сначала проверьте порядок выбора с [Fixed Status](/ru/behavior-trees/nodes/fixed-status) вместо реальных проверок и действий: ручной запуск загруженного дерева показан в [первом примере](/ru/behavior-trees/gettings-started). Так можно увидеть выбранную ветку до настройки игровых нажатий и источника готовности умения.

## Соберите два варианта атаки

Для примера нужны три уже настроенные ауры:

| Аура | Что делает |
| --- | --- |
| Умение готово | Активна, когда умение доступно. Например, проверяет его иконку. |
| Применить умение | Выполняет действие нажатия нужной клавиши. |
| Обычная атака | Выполняет базовую атаку. |

Добавьте в дерево Selector. Первым ребёнком сделайте Sequence из проверки Aura Is Active и действия Run Aura, вторым — ещё один Run Aura:

```text
Selector
├─ Sequence
│  ├─ Aura Is Active → «Умение готово»
│  └─ Run Aura → «Применить умение»
└─ Run Aura → «Обычная атака»
```

В Aura Is Active выберите ауру «Умение готово» и проверку её активного состояния. В каждом Run Aura выберите соответствующую ауру с действием. Расположите ветку умения первой в порядке обхода, обычную атаку — второй.

[Sequence](/ru/behavior-trees/nodes/sequence) объединяет проверку и применение умения в один вариант. Без неё проверка была бы отдельным ребёнком Selector: её успех остановил бы выбор ещё до атаки.

## Проверьте результат

Когда «Умение готово» активна, дерево должно пройти первую ветку и не выполнять обычную атаку. Когда условие не выполнено, Sequence возвращает Failure, а Selector переходит ко второму варианту.

Успешное нажатие клавиши само по себе не доказывает, что игра применила умение. Поэтому проверка готовности стоит перед действием, а результат в игре нужно проверить отдельно.

## Как Selector выбирает дальше

| Результат ребёнка | Поведение Selector |
| --- | --- |
| Failure | Пробует следующего ребёнка. Если вариантов больше нет, возвращает Failure. |
| Success | Возвращает Success; остальные варианты в этом обходе пропускает. |
| Running | Возвращает Running и запоминает этого ребёнка. При следующем обходе продолжает с него. |

Если первая ветка ещё выполняется, Selector не переходит к обычной атаке. В этот момент он также не начинает заново проверять более ранние варианты: это важно, если вы собираетесь добавить срочную ветку с более высоким приоритетом.

После завершения выбора следующий обход снова начинается с первого ребёнка. Порядок веток задаёт приоритет; отдельный параметр «приоритет» для этого не нужен.
