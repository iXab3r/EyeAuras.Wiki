# Как выбрать узел дерева

Сначала решите, что нужно: проверить условие, выполнить шаг, выбрать ветку или изменить результат ребёнка. Ниже — основные узлы EyeAuras со ссылками на их страницы. Это обзор, а не готовая программа и не список всех методов API.

## Статусы выполнения

| Результат | Как его читать |
| --- | --- |
| Success | Узел завершился успешно. Куда идти дальше, решает родитель |
| Failure | Узел завершился неуспешно. Для условия это обычно «не выполнено», а не ошибка программы |
| Running | Узел ещё не закончил. Родитель может запомнить место и продолжить со следующего тика |
| Пустой результат в интерфейсе | Узел ещё не запускался или его статус очищен. Это не четвёртый NodeStatus |

`Active`, `Not Active` и `Unknown` — это состояния триггеров и аур, а не узлов. Узел, который читает ауру, сам переводит её состояние в свой результат.

Ошибка и отмена не всегда выглядят как обычный `Failure`. При ручном запуске вы можете увидеть ошибку, а при автоматическом обходе корень может записать её и завершиться с `Failure`. Смотрите сообщение, а не только цвет.

## Подобрать минимальную схему

1. Если шаги идут один за другим, начните с `Sequence`. Если нужен один из вариантов, выберите `Selector` или `IfThenElse` по таблице ниже.
2. Сначала поставьте вместо настоящих проверок узлы `Fixed Status`. Так вы увидите маршрут без ввода и внешних данных. Для паузы добавьте `Wait`.
3. Запустите дерево через `Tick BT Once`, как в [первом примере](/ru/behavior-trees/gettings-started). Потом подключайте настоящие условия и реакции.

| Задача | Узел и что важно знать |
| --- | --- |
| Настроить загрузку, активацию и автоматический вход | [Root](/ru/behavior-trees/nodes/root): хранит настройки; автоматический вход — MainTree |
| Выполнить шаги по порядку | [Sequence](/ru/behavior-trees/nodes/sequence): идёт до первого Failure, на Running продолжает с того же места |
| Выбрать первый удачный вариант | [Selector](/ru/behavior-trees/nodes/selector): пропускает Failure, останавливается на Success или Running |
| Явно разделить условие, Then и Else | [IfThenElse](/ru/behavior-trees/nodes/ifthenelse): выполняет только выбранную ветку |
| Проверить состояние своих аур | [Aura Is Active](/ru/behavior-trees/nodes/aura-is-active): нужна уже настроенная аура |
| Вызвать действия своей ауры | [Execute Aura](/ru/behavior-trees/nodes/execute-aura): саму ауру настройте отдельно |
| Нажать клавишу | [Key Press](/ru/behavior-trees/nodes/KeyPress): это ввод, ему нужны правильное окно и способ доставки |
| Выдержать интервал | [Wait](/ru/behavior-trees/nodes/wait): ждёт время, а не событие |
| Ограничить частоту участка | [Cooldown](/ru/behavior-trees/nodes/cooldown): это не пауза перед следующим шагом |
| Поменять Success и Failure | [Inverter](/ru/behavior-trees/nodes/inverter): Running остаётся Running |
| Считать любой итог ребёнка Failure | [Force Failure](/ru/behavior-trees/nodes/force-failure): Running остаётся Running |
| Считать любой итог ребёнка Success | [Force Success](/ru/behavior-trees/nodes/force-success): Running тоже остаётся Running |
| Повторять попытки до успеха | [Until Success](/ru/behavior-trees/nodes/until-success): одна попытка ребёнка за тик, Failure становится Running |
| Временно задать исход проверки | [Fixed Status](/ru/behavior-trees/nodes/fixed-status): выбранное значение — это настройка, а не последний результат выполнения |
| Подписать участок схемы | [Comment](/ru/behavior-trees/nodes/comment): только пояснение, ничего не проверяет |
| Проверить, активно ли дерево поведения | [Is Active](/ru/behavior-trees/nodes/IsActive) |
| Проверить, удерживается ли клавиша | [Check Key State](/ru/behavior-trees/nodes/CheckKeyState) |
| Отфильтровать краткие изменения условия | [Debounce](/ru/behavior-trees/nodes/Debounce) |
| Прервать работу при выполнении условия | [Interrupter](/ru/behavior-trees/nodes/Interrupter) |
| Переместить указатель в заданную точку | [Mouse Move](/ru/behavior-trees/nodes/MouseMoveAbs) |
| Сместить указатель относительно текущей позиции | [Mouse Move Rel.](/ru/behavior-trees/nodes/MouseMoveRel) |

## Где взять узел

Кнопка `Add new Node` открывает список шаблонов, а `Toggle Nodes toolbar visibility` показывает боковую панель. Добавленный узел нужно соединить с родителем. Узел, который просто лежит рядом с линией, не выполняется.

В дереве поведения доступны шаблоны категории `Behavior Tree` и общие узлы. У макроса свои шаблоны — `Macro`. `Wait` и `IfThenElse` есть в обоих режимах, но работать они могут по-разному.

Набор узлов зависит и от подключённых модулей. Например, поиск изображения и `ML Search` приходят из OpenCV, `Key Press` и `Mouse Move` — из модуля ввода, `Aura Is Active` — из базовых аур. В списке могут быть и ваши деревья с отметкой `Is Shared`. Если шаблона в списке нет, не рассчитывайте, что то же самое можно вызвать одноимённым методом из скрипта.

У многих условий и действий может быть один ребёнок. Он выполняется только после `Success`, и итогом узла может стать его результат. Если шагов несколько, подключите `Sequence`. Как узел продолжает работу после Running, описано на его странице.
