# Как выбрать узел дерева

Сначала решите, что нужно сделать: проверить условие, выполнить шаг, выбрать ветку или изменить результат ребёнка. Ниже — вход в основные узлы EyeAuras. Это навигация по доступным механизмам, а не готовая программа и не список всех методов API.

## Статусы выполнения

| Результат | Как его читать |
| --- | --- |
| Success | Текущий вызов узла завершился успешно; дальнейший маршрут определяет родитель |
| Failure | Текущий вызов завершился с неуспехом. Для условия это обычно «не выполнено», а не обязательно ошибка программы |
| Running | Узел ещё не закончил работу. Родитель может сохранить место продолжения до следующего тика |
| Пустой результат в интерфейсе | Узел ещё не запускался либо его отображаемый статус очищен. Это не четвёртый NodeStatus |

`Active`, `Not Active` и `Unknown` принадлежат триггерам и аурам. Узел, читающий ауру, сам переводит её состояние в свой результат; не переносите эти названия на все узлы.

Исключение и отмена не равны обычному `Failure` во всех точках входа. Ручной запуск может показать ошибку, а корневой автоматический обход может записать её и завершиться с `Failure`. Смотрите сообщение, а не только цвет.

## Подобрать минимальную схему

1. Если шаги должны пройти один за другим, начните с `Sequence`. Если нужна одна из альтернатив, выбирайте `Selector` или `IfThenElse` по таблице.
2. Сначала замените реальные проверки узлами `Fixed Status`: так можно увидеть маршрут без ввода и внешних данных. Для временной задержки добавьте `Wait`.
3. Выполните выбранное дерево через `Tick BT Once` по [первому примеру](/ru/behavior-trees/gettings-started), затем подключайте настоящие условия и реакции.

| Задача | Узел и важная граница |
| --- | --- |
| Настроить загрузку, активацию и автоматический вход | [Root](/ru/behavior-trees/nodes/root): контейнер настроек; автоматический вход — MainTree |
| Выполнить шаги по порядку | [Sequence](/ru/behavior-trees/nodes/sequence): до первого Failure, с продолжением на Running |
| Выбрать первый удачный вариант | [Selector](/ru/behavior-trees/nodes/selector): пропускает Failure, останавливается на Success или Running |
| Явно разделить условие, Then и Else | [IfThenElse](/ru/behavior-trees/nodes/ifthenelse): выполняет только выбранную ветку |
| Проверить состояние своих аур | [Aura Is Active](/ru/behavior-trees/nodes/aura-is-active): нужна существующая настроенная аура |
| Вызвать действия своей ауры | [Execute Aura](/ru/behavior-trees/nodes/execute-aura): настройте вызываемую ауру отдельно |
| Нажать клавишу | [Key Press](/ru/behavior-trees/nodes/KeyPress): это ввод, требующий правильного адресата и способа доставки |
| Выдержать интервал | [Wait](/ru/behavior-trees/nodes/wait): ждёт время, а не наступление события |
| Ограничить частоту участка | [Cooldown](/ru/behavior-trees/nodes/cooldown): другая задача, чем пауза перед следующим шагом |
| Поменять Success и Failure | [Inverter](/ru/behavior-trees/nodes/inverter): Running остаётся Running |
| Принять терминальный исход ребёнка как Failure | [Force Failure](/ru/behavior-trees/nodes/force-failure): Running не превращает в завершение |
| Принять терминальный исход ребёнка как Success | [Force Success](/ru/behavior-trees/nodes/force-success): Running тоже сохраняется |
| Повторять попытки до успеха | [Until Success](/ru/behavior-trees/nodes/until-success): одна попытка ребёнка за тик, Failure становится Running |
| Временно задать исход проверки | [Fixed Status](/ru/behavior-trees/nodes/fixed-status): выбранный параметр отличается от последнего результата выполнения |
| Подписать участок схемы | [Comment](/ru/behavior-trees/nodes/comment): пояснение не заменяет выполняемую проверку |

## Где взять узел

Кнопка `Add new Node` открывает список шаблонов; кнопка `Toggle Nodes toolbar visibility` показывает боковую панель. В графе добавленный узел нужно соединить с родителем. Одна карточка рядом с линией ещё не является частью выполняемой цепочки.

Режим дерева поведения показывает шаблоны категории `Behavior Tree` и общие узлы; макрос использует отдельные шаблоны `Macro`. Похожие имена `Wait` и `IfThenElse` в этих двух режимах не гарантируют одинаковый контракт.

Набор зависит и от подключённых модулей. Например, поиск изображения и `ML Search` приходят из OpenCV, `Key Press` и `Mouse Move` — из модуля ввода, `Aura Is Active` — из базовых аур. Дополнительно в списке могут быть свои деревья, отмеченные `Is Shared`. Не считайте отсутствие шаблона доказательством, что его можно вызвать через одноимённый скриптовый метод.

У многих условий и действий есть один ребёнок: он выполняется только после `Success`, а итог может стать его результатом. Для нескольких шагов подключайте `Sequence`; особенности продолжения указаны на страницах конкретных узлов.
