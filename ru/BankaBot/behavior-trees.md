# Дерево поведения — разделить условия и действия BankaBot

Если выбор цели, расстояние и лечение начинают мешать друг другу, разнесите их по понятным веткам. В историческом описании BankaBot дерево было одним из способов задать поведение персонажа. Игровые признаки и команды должна предоставлять сама среда BankaBot — они не появляются в обычном дереве EyeAuras автоматически.

## Разобрать одну ветку до её настройки

Нужны поставка BankaBot с соответствующими узлами и описание источников игровых данных. Сначала определите, что уже есть в вашей конфигурации, не составляя дерево из придуманных названий узлов.

1. Выберите одну задачу, например действие по уже выбранной цели. Отдельно запишите источник цели и проверку допустимого расстояния.
2. Разделите проверку и реакцию: «цель подходит» допускает действие, но сама его не выполняет. Пропишите, какой результат означает отсутствие подходящей цели.
3. Определите более важное условие, например необходимость восстановления, если такая проверка и действие предоставлены поставкой. Не подменяйте их предположением, что любой узел умеет читать HP.
4. Для каждой ветки укажите завершение: условие не выполнено, действие закончено либо требуется продолжение. Затем сопоставляйте схему с реальными узлами своего редактора.

| Часть задачи | Что должно быть определено |
| --- | --- |
| Выбор цели | Источник объектов и критерий подходящей цели |
| Проверка расстояния | От каких объектов оно считается и в каких единицах |
| Действие или умение | Команда, её адресат и способ проверки результата |
| Ожидание и откат | Что именно ожидается: время, готовность действия или другое событие |
| Приоритет восстановления | Источник состояния персонажа и условие допуска этой ветки |
| Возврат к поиску | Как устанавливается, что предыдущая цель больше не подходит |

Результат этого этапа — одна понятная ветка с названными источниками и исходами, а не набор карточек с неподтверждёнными игровыми свойствами. От неё можно перейти к сочетанию поиска цели, действия, восстановления и повторного выбора после завершения цели.

## Как читать результат узла

| Статус дерева | Смысл |
| --- | --- |
| Success | Узел закончил свою проверку или работу успешно |
| Failure | Проверка не выполнена либо работа завершилась с таким исходом |
| Running | Работа ещё не завершена; дальнейший порядок задаёт контракт узла и родителя |

Не считайте периодический обход обещанием, что все ранние условия проверяются заново в каждый момент. В обычном EyeAuras составные узлы могут сохранять продолжение Running; для прерывания нужна соответствующая логика. У BankaBot проверяйте поведение конкретной версии и её узлов, а не переносите контракт похожего макроса.

Для знакомства с общим механизмом без игровых данных пройдите [первое дерево EyeAuras](/ru/behavior-trees/gettings-started) и [выбор узлов](/ru/behavior-trees/nodes). [Скрипты внутри деревьев](/ru/behavior-trees/scripting) имеют отдельный контекст исполнения; это не справочник игровых типов BankaBot.

## Когда подключать скрипт

Если задача требует нескольких событий, собственной математики или большого числа таймеров, часть работы удобнее вынести в [скрипт BankaBot](/ru/BankaBot/scripting/getting-started). Дерево при этом остаётся способом организовать приоритеты. Не начинайте с полной схемы всех ситуаций: сначала проверьте одну ветку по данным своей поставки и наблюдаемому результату, затем добавляйте следующую.
