# Скрипты — определить контекст и части логики BankaBot

Чтобы независимо настраивать восстановление, уведомления или отображение, сначала разделите логику на части и определите её зависимости. Прежнее описание BankaBot предусматривало C#-скрипты в среде EyeAuras с дополнительным игровым контекстом. Это не означает, что любой Script.csx видит персонажа и его цель.

## Подготовить задачу для своей среды

Нужны конкретная поставка BankaBot, её проект или примеры и соответствующее описание API. Обычный SDK EyeAuras даёт общие контракты платформы; типы персонажа, группы и игровые события должна добавлять среда BankaBot.

1. Выберите одну небольшую задачу: например, вывести метку по уже предоставленному состоянию объекта. Отдельно укажите, откуда приходит это состояние и где должен появиться результат.
2. Найдите в проекте своей поставки реальные типы и пример обращения к ним. Не заменяйте неизвестный игровой API придуманным свойством или значением из другого примера.
3. Разделите части с разной ответственностью: получение состояния, решение и отображение. Для каждой запишите условие включения и момент прекращения работы.
4. Определите контекст кода и владельца ресурсов. Только после этого выбирайте дерево, одну группу скрипта или отдельный класс проекта.

Результат подготовки — конкретный источник данных, ожидаемая реакция и граница жизни одной части сценария. Например, группа отображения использует уже полученные данные объекта и владеет своими метками; отключение другой группы не должно случайно менять её источник.

| Возможность из описания BankaBot | Что нужно получить от соответствующей среды |
| --- | --- |
| Персонаж, цель, группа и окна игры | Реальные игровые типы и способ обращения к ним |
| Клавиатура и мышь | Настроенного адресата и доступный механизм ввода |
| OSD | Контекст отображения и владельца созданных элементов |
| Таймеры | Правила запуска, повторения и остановки работы |
| Системные и сетевые сообщения | Источник событий и их точный формат |
| Нажатия клавиш | Регистрацию обработчика и срок её действия |
| Телепорт или резкая смена позиции | Событие либо критерий изменения, предоставленный BankaBot |

Эти перечисления описывают предусмотренные задачи, а не имена методов для вставки в любой C#-файл. Геодата также не заменяет этот контекст: она описывает проходимость мира, а не выдаёт все текущие объекты и события.

## Группы вместо одного большого сценария

В прежнем описании группы можно было включать и выключать отдельно через виджеты-кнопки. Пример разделения:

| Группа | Одна ответственность |
| --- | --- |
| Бой | Работа по выбранной цели |
| Бафы | Отдельные сроки и условия поддерживающих действий |
| Лут | Действия подбора после нужного события |
| Уведомления | Сообщения о выбранных состояниях |
| Перемещение | Маршрут и условия движения |

Выбор групп не определяет автоматически, как завершаются уже начатые операции. Подписки, окна, таймеры и элементы OSD должны принадлежать своему владельцу и освобождаться по контракту среды. Остановка одной группы не является универсальной отменой любого кода.

## C#, проекты и помощник

Описание BankaBot допускало NuGet-пакеты, несколько файлов проекта и сочетание скриптов с [деревом поведения](/ru/BankaBot/behavior-trees); сам бот также описывался как скрипт внутри EyeAuras. Наличие пакета с типами не означает наличие живых сервисов в каждом хосте.

В верхнеуровневом Script.csx EyeAuras может предоставлять Log, GetService и cancellationToken. Обычный C#-класс получает зависимости явно, компонент Razor — через предусмотренную передачу или внедрение зависимостей. Ресурс своего запуска освобождайте в явном блоке или другом поддержанном контексте владения; директивы using остаются сверху. Подробности общего хоста — в [основах C# Script](/ru/scripting/getting-started) и [контракте исполнения](/ru/scripting/api/scripting/runtime).

AI Code Assistant в прежнем описании помогал писать и менять код, а также искать сведения по API. Чтобы запрос был полезен, дайте ему реальные типы и контекст своего проекта, входные данные и ожидаемый результат. Помощник не создаёт отсутствующую игровую интеграцию и не заменяет проверку контракта поставки.
