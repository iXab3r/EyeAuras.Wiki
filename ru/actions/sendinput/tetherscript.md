# Ввод через TetherScript Driver

Если на компьютере уже подготовлен драйвер виртуальной клавиатуры Tetherscript, его можно выбрать для короткой команды в обычном приложении. Например, Send Sequence может открыть поиск в браузере клавишей F3 через этот механизм ввода.

EyeAuras передаёт команды виртуальным HID-устройствам драйвера — клавиатуре и мыши. Само приложение ControlMyJoystick для выполнения последовательности не требуется. На схеме показана только цепочка доставки; слово Game не означает встроенную интеграцию с конкретной игрой.

![EyeAuras передаёт ввод через драйвер целевому приложению](https://s3.eyeauras.net/media/2025/07/ChatGPT%20Image%20Jul%2014%2C%202025%2C%2003_09_58%20PM.png =x200)

## Что подготовить

Нужны EyeAuras с механизмом ввода **TetherScript Driver**, установленный совместимый драйвер Tetherscript и обычное окно, принимающее клавиатуру. Для примера откройте страницу в браузере, где ручное F3 открывает поиск. Начните с клавиатуры: наличие одного виртуального устройства ещё не проверяет все режимы мыши.

Если драйвер не установлен, используйте [ControlMyJoystick на сайте производителя](https://tetherscript.com/controlmyjoystick-home/). Кнопка **Install...** у этого механизма ввода открывает страницу загрузки и после установки повторно проверяет устройства. По [README производителя HVDK](https://github.com/tetherscript/hvdk) драйверы из пробной установки продолжают работать без покупки ControlMyJoystick.

HVDK как отдельный продукт снят с поддержки. [Зеркало HVDK Standard 2.1](https://s3.eyeauras.net/media/2024/10/HVDK%20Standard%202.1.exe) сохранено для старых установок; не считайте его подтверждением совместимости с любой современной Windows. Требования и установку проверяйте для конкретной версии драйвера у производителя. Если установщик требует перезагрузку, завершите её до настройки ввода.

## Выбрать драйвер и открыть поиск

1. Создайте тестовую ауру и добавьте **Send Sequence**. Через **Fn → F3** добавьте пару событий с задержкой между Down и Up.
2. В **Advanced input settings → Target Window** выберите окно браузера. В **Input Simulator** выберите **TetherScript Driver**.
3. Проверьте готовность механизма ввода. Если предлагается Install..., сначала завершите подготовку драйвера. Для этого опыта оставьте **Block User input = None**, а **Key/Button State** включите.
4. Сделайте страницу текущей вкладкой и нажмите **Execute** у действия. Должна открыться панель поиска браузера так же, как при ручном F3. Если она не открылась, проверьте выбранное окно, фокус и готовность виртуальной клавиатуры.
5. Закройте поиск вручную и повторите короткую команду. Только после этого назначайте этот способ ввода остальным действиям.

На старом снимке раскрыт выбор способа ввода у Send Sequence. В текущем редакторе он также находится в Advanced input settings; оформление списка отличается.

## Настроить область применения

| Где выбрать Input Simulator | На что влияет |
|---|---|
| Advanced input settings у Send Sequence | На это действие. Удобно для первой отдельной проверки |
| Folder Properties → Triggers/Actions/Overlays Defaults | На компоненты, использующие значение по умолчанию этой папки. У существующих действий проверьте привязки; Apply to All применяет выбранные свойства по области папки |
| Свойства корня Macro / Behavior Tree | На ввод, использующий настройки этого макроса или дерева. Это другой редактор, а не старое действие Send Text |

Настройка папки полезна, когда драйвер должен использоваться всей группой. Не назначайте одновременно противоречащие друг другу значения на нескольких уровнях: [наследование и Apply to All](/ru/features/default-properties) объясняют, какие индивидуальные настройки будут заменены.

Снимок папки показывает включённое поле Input Simulator и выбранный способ ввода:

![Input Simulator в настройках папки](https://s3.eyeauras.net/media/2025/07/NVIDIA_Overlay_w4H6swrVSxeI4uGV.png =x400)

Снимок макроса показывает выбор в свойствах его корневого узла. Для дерева выбирают Root; для макроса — его корневую строку.

![Выбор способа ввода в свойствах корня макроса](https://s3.eyeauras.net/media/2025/07/NVIDIA_Overlay_N4kvjMqSsIqbaVhH.png =x600)

## Ограничения

| Особенность | Что учитывать |
|---|---|
| Виртуальные HID-устройства | EyeAuras использует драйверные устройства клавиатуры и абсолютной/относительной мыши. Это не доступ к внутренним данным приложения |
| Target Window | Перед вводом целевое окно активируется. Драйвер не превращает обычную клавиатуру в универсальный ввод в свёрнутое окно |
| Готовность | Проверка установленности может обнаружить клавиатуру или абсолютную мышь; конкретное нужное действие всё равно проверяйте отдельно |
| Совместимость | Приём ввода зависит от приложения и его окружения. Работа драйвера не означает, что он невидим или разрешён любым приложением |

Если требуется физическое устройство вместо виртуального драйвера, у [Usb2Kbd](/ru/actions/sendinput/usb2kbd) другие требования к подготовке и протокол. Сравнение способов доставки — в [общих параметрах](/ru/actions/sendinput/options).
