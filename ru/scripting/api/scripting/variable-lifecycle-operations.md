# Выбрать владельца и время жизни переменной

Два дескриптора с одинаковым именем обращаются к одной записи, только если у
них один владелец. `Variables.Get<int>("count")` использует текущий контекст
скрипта. Перегрузка с путём выбирает конкретную ауру, папку или другой
поддерживаемый элемент дерева. Ни одна из них не создаёт этот элемент.

Код ниже выполняется в C# Script внутри EyeAuras. `Variables`, `AuraTree`,
`Log` и `cancellationToken` предоставляет хост. Обычному классу передайте
`IVariablesScriptingApi` или готовый `ScriptVariable<T>` явно; дополнительных
NuGet-пакетов для этих операций не требуется.

## Наследовать настройку и отменить локальное переопределение

Создайте в корне Aura Tree отдельную папку `DocVariables` и в ней ауру
`Probe`. Выполните пример из C# Script. Он меняет только демонстрационную
переменную `doc.delayMs` у этих двух элементов.

```csharp
using System.Reactive.Linq;

{
    var folder = Variables.Get<int>("DocVariables", "doc.delayMs");
    var aura = Variables.Get<int>("DocVariables/Probe", "doc.delayMs");

    aura.Remove();
    folder.Value = 250;
    using var subscription = aura.Listen()
        .Subscribe(value => Log.Info($"Задержка ауры: {value}"));

    aura.Value = 500;
    aura.Remove();
    Log.Info($"Папка: {folder.Value}, аура: {aura.Value}");

    var result = aura.Remove();
    Log.Info($"Повторное Remove: {result}, значение: {aura.Value}");
}
```

Подписчик получает `250`, `500`, затем снова `250`. Запись в ауру создаёт
локальное переопределение, не меняя папку. Удаление этого переопределения
возвращает родительское значение. Подписка освобождается в конце блока;
папка сохраняет `doc.delayMs = 250` в своём текущем хранилище.

**У `Remove()` есть особенность этой реализации:** повторное удаление в
примере тоже возвращает `true`, хотя локального переопределения уже нет.
Метод сначала ищет имя среди эффективных значений, включая наследуемые, а
удаляет только локально. Родительская запись остаётся на месте. Поэтому
результат `true` не доказывает ни удаление локальной записи, ни исчезновение
переменной. Проверяйте нужное вам состояние после операции.

`HasValue`, `Variables.Contains(name)`, `Count` и перечисление тоже относятся
к эффективному набору значений владельца, а не только к локальным записям.
Локальный `null` перекрывает родительское значение: `HasValue` остаётся
`true`, но типизированное чтение возвращает `default(T)` или `false`.

`Listen()` сообщает отличающиеся эффективные значения. Если при удалении
или изменении родителя значение осталось тем же, отдельного уведомления
может не быть. Уведомления не обещают UI-поток.

## Правильно указать путь

Путь без `./` или `../` задаётся от корня дерева. Например,
`DocVariables/Probe` выбирает созданную выше ауру независимо от расположения
скрипта. Начальный разделитель добавлять не нужно. `/` и `\` допустимы как
разделители пути дерева.

Префиксы `./` и `../` разрешаются относительно `Context.Path` текущего
контекста. Это не путь к `Script.csx` на диске. Перед использованием
относительного пути проверьте, какой объект выполняет скрипт.

Особый путь `"."` у `AuraTree.GetAuraByPath` означает текущую ауру. Но
`Variables.Get<T>(".", name)` проходит через общий поиск элемента по пути,
без этого специального правила. Не используйте его как замену
`Variables.Get<T>(name)`. Если объект уже найден, передайте его явно:

```csharp
var owner = AuraTree.GetAuraByPath("DocVariables/Probe");
var count = Variables.Get<int>(owner, "doc.count");
count.Value = 3;
Log.Info($"Счётчик выбранной ауры: {count.Value}");
```

Если элемента по пути нет, перегрузка `Get<T>(path, name)` бросает
`ArgumentException` до чтения переменной. Полученный дескриптор привязан к
найденному объекту, а не выполняет поиск по строке при каждом чтении.
Не переносите его за время жизни владельца. Доступ к владельцу заимствован:
ради работы с переменной не вызывайте у него `Dispose()`.

## Что остаётся после повторного Run

Следующий пример сравнивает три разных места хранения. Для наблюдения
запустите один и тот же скрипт дважды без изменения кода и контекста.
Имя `doc.runs` должно быть новым для этого контекста.

```csharp
int InstanceRuns { get; set; }

var localRuns = 0;
localRuns++;
InstanceRuns++;
var ownerRuns = Variables.Get<int>("doc.runs");
ownerRuns.Value++;

Log.Info($"Локально: {localRuns}, экземпляр: {InstanceRuns}, владелец: {ownerRuns.Value}");
```

При сохранении одного экземпляра скрипта первый запуск даёт `1, 1, 1`,
второй — `1, 2, 2`. Локальная переменная создаётся заново. Свойство живёт
в экземпляре скомпилированного скрипта. Запись `doc.runs` находится у
владельца, на которого указывает `Variables`.

Runner повторно использует контекст при неизменной версии проекта. Само
изменение другой части workspace ещё не обязательно пересоздаёт его. При
изменении зависимой версии проекта создаётся новый контекст, поэтому на
сохранение `InstanceRuns` после редактирования рассчитывать нельзя.
Пересоздание контекста выполнения само по себе не удаляет переменные
сохранившегося владельца; замена или выгрузка самого владельца — другая
граница времени жизни.

`ExecutionAnchors` создаётся отдельно для каждого выполнения и освобождается
при его завершении, включая остановку. Для подписки на время текущего Run
можно использовать `using` и ожидаемую отменяемую операцию, как в
[примерах асинхронности](/ru/scripting/api/scripting/async). Подписка сама
по себе не удерживает Run открытым. Не храните её в свойстве экземпляра в
расчёте на следующий запуск.

## Что будет после перезапуска приложения

Обычная переменная владельца — состояние в памяти, а не обещание записи
любого объекта на диск. В проверенном адаптере настроек сериализуются
локальные непустые значения `default.*`, причём ненулевое значение должно
быть строкой. Это специальный механизм настроек подсистем, не универсальное
хранилище для произвольных объектов скрипта. Не добавляйте префикс `default.`
своим данным только ради сохранения.

Для долговременных настроек используйте подходящий
[провайдер конфигурации](/ru/scripting/api/core/configuration-persistence).
Он требует собственной регистрации и правил сохранения; типизированный
дескриптор переменной его не заменяет.
