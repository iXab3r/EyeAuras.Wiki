# Карта переменных в EyeAuras

Справочная карта по переменным, доступным из скриптов, типизированным обращениям к переменным, иерархии переменных аур и папок, `default.*` переменным и реактивным подпискам на изменения.

Для готовых сценариев наследования, удаления переопределения, выбора пути и
повторного Run начните с
[владельцев и времени жизни переменных](variable-lifecycle-operations).

## Для чего это нужно

- Хранить небольшие настройки вне локальных переменных C#.
- Делиться значениями между скриптами, аурами, папками и поведением.
- Безопасно читать и записывать типизированные значения переменных.
- Отслеживать изменения переменных.
- Использовать значения папки как значения по умолчанию для вложенных аур.
- Понять, почему чтение переменной вернуло значение по умолчанию.
- Отличать поля скрипта на время выполнения от постоянных переменных ауры или папки.

## Модель работы

- Локальные переменные C# живут только внутри одного метода или одного запуска.
- Поля и свойства класса скрипта живут до перекомпиляции скрипта или пересоздания sandbox.
- Переменные ауры, папки и скрипта хранятся в контейнерах переменных EyeAuras.
- Переменные могут быть видны в UI у той ауры или папки, которой они принадлежат.
- `IVariablesScriptingApi` — API переменных со стороны скрипта.
- `ScriptVariable<T>` — типизированный доступ к именованной переменной.
- Ауры и папки реализуют контейнеры переменных через `IHasVariables`.
- Переменные папки могут работать как наследуемые значения по умолчанию для вложенных элементов.
- Переменные вида `default.*` обычно используют для настройки поведения подсистем по умолчанию вниз по дереву аур.

## Что есть в API

- `IVariablesScriptingApi` — основной API переменных для скриптов.
- `Variables["name"]` — прямой доступ через индексатор как к `object`.
- `Variables.Get<T>("name")` — типизированная переменная для текущего скрипта или контекста.
- `Variables.Get<T>(path, "name")` — типизированная переменная из другой ауры или папки.
- `Variables.Get<T>(IHasVariables, "name")` — типизированная переменная из известного источника.
- `ScriptVariable<T>` — типизированный доступ к переменной.
- `ScriptVariable<T>.Value` — безопасное чтение и запись; возвращает `default(T)`, если значение отсутствует, равно `null` или несовместимо по типу.
- `ScriptVariable<T>.HasValue` — `true`, если запись существует в хранилище.
- `ScriptVariable<T>.TryGetValue(out T value)` — попытка прочитать и преобразовать значение.
- `ScriptVariable<T>.GetOrThrow()` — строгое чтение с исключением для обязательных значений.
- `ScriptVariable<T>.Set(value)` — удобная fluent-запись.
- `ScriptVariable<T>.Remove()` — удаляет запись.
- `ScriptVariable<T>.Listen()` — observable-поток типизированных значений.
- `IBindingValueConverterRepository` — поддержка преобразований, которая используется при типизированном чтении.

## Семантика значений

- Чтение `Value` у корректно полученного дескриптора возвращает значение по умолчанию при отсутствии записи или неудачном преобразовании.
- `Value` возвращает `default(T)`, если переменной не существует.
- `Value` возвращает `default(T)`, если сохранённое значение нельзя преобразовать.
- `HasValue` означает, что запись существует, даже если сохранённое значение равно `null`.
- `TryGetValue` возвращает `false`, если значение отсутствует, равно `null` или несовместимо по типу.
- `GetOrThrow` нужен для обязательных значений, когда отсутствие или несовпадение типа считается ошибкой.
- `Remove` удаляет локальную запись. После этого может стать видимым родительское значение; если его нет, чтение даёт `default(T)`.
- `Listen` сначала отдаёт текущее значение, затем только отличающиеся изменения.

У `ScriptVariable<T>.TryGetValue` и `Value` нет универсальной гарантии отсутствия
исключений: преобразование структуры из другого контекста загрузки использует
JSON без перехвата ошибок сериализации. Отсутствующая запись и `null` дают
обычный запасной результат; ошибка самого преобразователя — другая ситуация.
Также не путайте метод handle с `Variables.TryGetValue<T>(name, out value)`:
последний прямо приводит сохранённый объект к `T` и может бросить ошибку типа.

## Иерархия

- Переменные аур и папок образуют древовидную иерархию настроек.
- Дочерний элемент может читать унаследованные значения из родительских папок.
- Дочерний элемент может локально переопределить родительское значение.
- Переменные на уровне папки удобно использовать для целевых окон, режима ввода, общих имён профилей, задержек и других групповых настроек.
- Имена вроде `default.WindowSelector.TargetWindow` и других `default.*` могут влиять на значения подсистем по умолчанию для вложенных элементов.

## Прочитать настройку с запасным значением

Этот пример выполняется в C# Script внутри EyeAuras. `Variables` и `Log` предоставляет `AuraScriptSandbox`; в обычном классе передайте `IVariablesScriptingApi` через конструктор или параметр.

```csharp
var delay = Variables.Get<int>("delayMs");
var delayMs = delay.TryGetValue(out var savedDelay) ? savedDelay : 250;
Log.Info($"Задержка: {delayMs} мс");
```

В логе появится сохранённое значение либо `250`, если записи нет, она равна `null` или её не удалось преобразовать. `Value` в этих случаях возвращает `default(int)`, то есть `0`, поэтому не отличает отсутствие настройки от сохранённого нуля. `HasValue` проверяет наличие записи, а не пригодность её значения для выбранного типа.

## Записать значение и прочитать его повторно

В C# Script используйте один и тот же тип и имя:

```csharp
var count = Variables.Get<int>("operationCount");
count.Value = 7;
Log.Info($"Сохранено: {count.GetOrThrow()}");
```

В логе будет `7`. `Get<T>` возвращает небольшой типизированный дескриптор, а не копию значения; другой дескриптор для того же источника и имени обращается к той же записи. `GetOrThrow()` возвращает обязательное значение или бросает `InvalidOperationException`, если оно отсутствует, равно `null` или не может быть прочитано выбранным типом. Не полагайтесь на одинаковые преобразования у `GetOrThrow()` и `TryGetValue()` для произвольных объектов — в рассматриваемой версии их пути преобразования различаются.

Для переменной другой ауры или папки есть `Variables.Get<T>(itemPath, variableName)` и `Variables.Get<T>(source, variableName)`, где `source` реализует `IHasVariables`. Путь должен указывать на существующий элемент; получение дескриптора по отсутствующему пути бросает `ArgumentException`.

## Наблюдать за изменением и удалить запись

Следующий законченный C# Script создаёт подписку, меняет значение и удаляет запись. `using` ограничивает подписку этим выполнением.

```csharp
using System.Reactive.Linq;

{
    var level = Variables.Get<int>("exampleLevel");
    level.Value = 1;
    using var subscription = level.Listen()
        .Subscribe(value => Log.Info($"Уровень: {value}"));
    level.Value = 2;
    var removed = level.Remove();
    Log.Info($"Запись удалена: {removed}");
}
```

Если у родителя нет одноимённой переменной, подписчик получает текущее значение `1`, затем `2`, затем `0` после удаления. При наличии родительского значения оно снова становится видимым. Повторяющиеся значения отсекаются через `DistinctUntilChanged`; удаление не обещает отдельного события, если эффективное значение не изменилось. `Remove()` возвращает `true`, если имя было видно перед вызовом, включая унаследованное значение. Это не подтверждает удаление локальной записи или исчезновение эффективного значения. Для долгоживущего интерфейса привяжите подписку к его владельцу; сам `Listen()` не задаёт UI-поток.

## Что предпочитать

- Предпочитайте `ScriptVariable<T>`, а не прямой доступ через индексатор как к `object`.
- Для необязательных значений предпочитайте `TryGetValue`.
- Для обязательной конфигурации предпочитайте `GetOrThrow`.
- Для общих настроек связанных аур предпочитайте переменные папки.
- Используйте понятные имена и единый стиль или префиксы.
- Освобождайте подписки `Listen()` вместе со временем жизни владельца.

## Чего избегать

- Не считайте `Value == default(T)` доказательством того, что переменная отсутствует.
- Не используйте прямой доступ через индексатор там, где важна типобезопасность.
- Не храните в переменных живые handles, окна, процессы или disposable-объекты.
- Не злоупотребляйте глобальными и общими переменными для значений, которым место в локальном состоянии.
- Не считайте имена `default.*` безобидными — они могут влиять на вложенные системы.

## ScriptVariable Listen и время жизни shared state

`Variables.Get<T>` возвращает `ScriptVariable<T>` для выбранного `IHasVariables`.
Для typed variable читайте `Value`, `TryGetValue` или `GetOrThrow`; `HasValue`
проверяет присутствие, а `IBindingValueConverterRepository` участвует в приведении
типов. Нетипизированные `IScriptVariable` и индексатор `Variables.Item` нужны
только там, где контракт действительно использует `object`.

`Listen()` даёт текущие и последующие отличающиеся значения reactive variable;
подписку освобождает вызывающий код. Для lifetime одного Run используйте
`using` в блоке выполнения или `ExecutionAnchors`. Unload сам не освобождает
вашу подписку. [Примеры времени жизни](/ru/scripting/api/scripting/variable-lifecycle-operations)
показывают завершение Run, редактирование, выгрузку и выбор владельца.

Aura variables и folder variables образуют variable hierarchy: наследуемое
значение становится видимым после `Remove()` локального переопределения.
Это shared state / blackboard в памяти владельца, не произвольное постоянное
хранилище. Для persistent setting используйте провайдер конфигурации.
Имена default variable вроде `default.WindowSelector.TargetWindow` относятся
к настройкам подсистем; не используйте `default.*` ради сохранения своих данных.
