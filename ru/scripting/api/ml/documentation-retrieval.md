# Найти контракт через инструменты документации

В обычном AI-чате EyeAuras поиск документации работает с локальным снимком Wiki.
Публикация статьи на сайте и обновление этого снимка — разные операции.

## Найти операцию и прочитать исходный текст

1. Включите базу знаний в настройках AI и запустите сессию **Standard Chat**.
2. Попросите вызвать `doc_search` с точным именем API и задачей, например
   `ScriptVariable Listen lifetime`.
3. Прочитайте найденный `chunkId` через `doc_get_chunk_full`. Заголовок и
   короткое превью помогают выбрать результат, но не заменяют контракт и код.
4. Для ссылки на статью используйте `Link` из результата. У английских страниц
   это `/en/...`, у русских `/ru/...`; путь файла с `.md` остаётся идентификатором
   документа внутри индекса.

Для конкретного документа у `doc_search` есть `docName`; `kind` и `tagsCsv`
фильтруют только метаданные, которые действительно были загружены. Не угадывайте
метки по содержимому: сначала посмотрите их через `doc_list_documents`.

Длинный фрагмент может потребовать нескольких вызовов. `doc_get_chunk_full`
возвращает до 20 000 символов за вызов и указывает смещение продолжения, если
остался текст. Передавайте этот `offset` с тем же `chunkId`, пока продолжений
не останется. Частичный ответ может закончиться внутри кода — это ещё не
полный пример.

## Какие страницы попадают в базу

Desktop и бот исключают статьи с явным `published: false`. Отсутствие этого
поля не равнозначно запрету публикации. Опубликованные карты `scripting/api/AGENTS.md`
остаются документацией; имя файла само по себе не делает страницу внутренней.

Загрузчик читает плоские поля `description`, `kind`, `tags`, `published` из
frontmatter. Метки поддерживают строку через запятую и список в квадратных
скобках. Заголовок frontmatter не попадает в текст поискового фрагмента.
Сложные вложенные YAML-объекты не являются форматом этих метаданных.

## Обновить desktop-снимок и проверить его версию

Для **Standard Chat** сохраните настройки AI кнопкой **Save**, затем начните
новую сессию или сбросьте текущую. Сохранение сбрасывает подготовленную базу;
следующая инициализация обновляет Git-каталог и строит новый индекс. Уже открытая
сессия продолжает пользоваться своим снимком до пересоздания.

`doc_get_index_status` возвращает:

- `SourceRevision` — Git SHA снимка, загруженного desktop-провайдером;
- `IndexHash` — идентификатор содержимого и настроек индекса;
- `DocumentCount`, `ChunkCount`, `IsIndexed` и `IsDirty` — состояние этой базы.

У общего `AiDocsKnowledgeBasePlugin`, созданного другим приложением, ревизия
может отсутствовать: её передаёт владелец источника. `doc_reindex` перестраивает
индекс уже загруженных документов; он **не выполняет Git fetch**.

Кнопка **Rebuild** в разделе **Guidance pack** обновляет отдельный набор файлов
для внешних инструментов. SHA этого набора не доказывает, что существующая
Standard Chat-сессия уже использует тот же индекс. Обновление сайта из `main`
каждые 15 минут тоже не обновляет открытый desktop-чат.

## Контракты и связанные области

Типы `AiDocsKnowledgeBasePlugin`, `Bm25Document`, `Bm25SearchHit` и
`Bm25IndexStatus` находятся в `EyeAuras.AI.BM25`. `SourceUrl` у документа задаёт
каноническую ссылку независимо от его имени в индексе; общие загрузчики могут
передавать собственный URL. Интерпретация `published` относится к адаптеру
источника, а не к механизму ранжирования.
