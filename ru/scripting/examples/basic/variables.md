# Сохранить счётчик между запусками скрипта

В этом примере каждый `Run` увеличивает счётчик, и правка кода скрипта его не сбрасывает. Для этого значение пишут не в локальную C#-переменную, а через `Variables` в хранилище владельца.

Нужен собственный редактируемый `C# Script`. Примеры выполняются в его верхнеуровневом `Script.csx`: `Variables`, `AuraTree` и `Log` там даёт EyeAuras. В обычный класс нужные службы передают явно.

1. Создайте новое действие `C# Script`. Ни у него, ни у его предков ещё не должно быть переменной `myCounter`.
2. Замените код типизированным счётчиком:

```csharp
var myCounter = Variables.Get<int>("myCounter"); // инициализируем переменную типа int с именем myCounter
myCounter.Value = myCounter.Value + 1; // увеличиваем значение на 1
Log.Info($"Counter value: {myCounter.Value}"); // в новом контексте получится 1, затем 2, 3 и т.п.
```

3. Нажмите `Run`. Целой переменной ещё нет, поэтому она читается как `0`, а после записи в журнале появится `Counter value: 1`.
4. Нажмите `Run` ещё раз — будет `Counter value: 2`. Добавьте в код комментарий, дождитесь компиляции и запустите снова. Значение продолжит расти, пока владелец переменной тот же.
5. Откройте `Variables` у выбранного владельца и найдите там запись и её значение.

В текущем редакторе ещё есть `Add variable...`, правка значения с кнопкой `Save` и удаление через `Remove`. Ручной ввод может изменить тип значения.

## Выбрать время жизни данных

| Место хранения | Что сохраняется |
| --- | --- |
| Локальная переменная C# | Живёт только до выхода из своего блока или метода. |
| Поле или свойство [песочницы](/ru/scripting/sandbox) | Живёт между запусками одного экземпляра песочницы. Перекомпиляция или пересоздание экземпляра сбрасывает поля. |
| `Variables` текущего скриптового контекста | Запись у владельца, которая переживает перекомпиляцию кода. Другое действие с тем же именем переменной не обязательно использует того же владельца. |
| Переменная ауры или папки | Данные выбранного узла, которые наследуют дочерние узлы. К общему владельцу можно явно обратиться из нескольких скриптов. |

Простые поддерживаемые значения попадают в сохраняемую конфигурацию. Но произвольный .NET-объект от этого не становится пригодным для записи на диск.

<details>
<summary>Локальная переменная, свойство и индексатор</summary>

Локальная переменная для счётчика между запусками не подходит:

```csharp
var test = 123;
```

Свойство живёт дольше, но только в одном экземпляре песочницы. Этот отдельный пример каждый раз записывает `16`, а не увеличивает значение:

```csharp

int MyCounter { get; set; }

// здесь много-много вашего кода

MyCounter = 16;

// здесь еще больше кода

Log.Info($"Counter: {MyCounter}");

```

Число записей текущего контекста можно вывести так:

```csharp
Log.Info($"Variables count: {Variables.Count}");
```

Индексатор работает с `object`. Этот фрагмент каждый раз перезаписывает значение единицей:

```csharp
Variables["myCounter"] = 1; // записываем 1 в переменную с именем myCounter
Log.Info($"Counter value: {Variables["myCounter"]}"); // считываем значение переменной myCounter, будет 1
```

Поэтому для арифметики нужно приведение типа. Этот самостоятельный фрагмент сначала пишет `1`, затем получает `2`:

```csharp
Variables["myCounter"] = 1; // записываем 1 в переменную с именем myCounter
// Variables["myCounter"] = Variables["myCounter"] + 1; // не сработает и выдаст ошибку!

Variables["myCounter"] = (int)Variables["myCounter"] + 1; // а вот это уже сработает
Log.Info($"Counter value: {Variables["myCounter"]}"); // в myCounter будет 2
```

Типизированный `Variables.Get<int>` из основного примера задаёт имя и тип один раз. Его `Value` читает и записывает хранилище. Вызывать `Dispose` у дескриптора не нужно.

</details>

## Передать значение другой ауре

Создайте рядом со скриптом собственную ауру `Something`. Ниже два **альтернативных** фрагмента. Оба записывают `16` в её `myCounter` и счётчик текущего скрипта дальше не увеличивают.

По относительному пути:

```csharp
// Создайте рядом со скриптом ауру Something.
var auraVariable = Variables.Get<int>(@".\Something", "myCounter");
auraVariable.Value = 16;
```

Или через найденный узел:

```csharp
var aura = AuraTree.GetAuraByPath(@".\Something");
var auraVariable = Variables.Get<int>(aura, "myCounter");
auraVariable.Value = 16;
```

Путь отсчитывается от текущего контекста дерева. Точные варианты вызовов — в [Variables API](/ru/scripting/api/IVariablesScriptingApi).

Чтобы видеть общее значение и не перечитывать журнал, используйте [экранную таблицу переменных](/ru/scripting/examples/basic/print-variables-on-screen). Источником укажите ту же ауру, в которую пишет скрипт, и добавьте имя переменной в список строк.

## Как работает наследование

Значение папки доступно её дочерним узлам. Локальная запись с тем же именем перекрывает унаследованную. Удалите локальную запись — и снова будет видно значение предка. Это похоже на [наследование CSS](https://en.wikipedia.org/wiki/CSS): ближняя настройка важнее.

Так же расходятся и значения по умолчанию. Например, `default.WindowSelector.TargetWindow` влияет на выбор окна во вложенных аурах. Не меняйте такие служебные имена ради проверки счётчика.

Чем отличаются отсутствующая запись, `null`, значение по умолчанию и подписка, разобрано в [типизированных операциях](/ru/scripting/api/scripting/variables). Законченный пример с общим владельцем, `Remove()` и повторным `Run` — в [руководстве по времени жизни](/ru/scripting/api/scripting/variable-lifecycle-operations).
