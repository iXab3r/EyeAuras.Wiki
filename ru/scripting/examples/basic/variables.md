# Сохранить счётчик между запусками скрипта

Пусть каждый `Run` увеличивает счётчик, а изменение текста скрипта не сбрасывает его. Для этого значение записывают в хранилище владельца через `Variables`, а не в локальную C#-переменную.

Нужен собственный редактируемый `C# Script`. Примеры выполняются в его верхнеуровневом `Script.csx`: `Variables`, `AuraTree` и `Log` предоставляет EyeAuras. В обычный класс нужные службы передают явно.

1. Создайте новое действие `C# Script`, в контексте которого и у его предков ещё нет переменной `myCounter`.
2. Замените код типизированным счётчиком:

```csharp
var myCounter = Variables.Get<int>("myCounter"); // инициализируем переменную типа int с именем myCounter
myCounter.Value = myCounter.Value + 1; // увеличиваем значение на 1
Log.Info($"Counter value: {myCounter.Value}"); // в новом контексте получится 1, затем 2, 3 и т.п.
```

3. Нажмите `Run`: отсутствующее целое значение читается как `0`, после записи журнал покажет `Counter value: 1`.
4. Повторите `Run`: получится `Counter value: 2`. Добавьте комментарий в код, дождитесь компиляции и запустите ещё раз — значение продолжит расти, пока используется тот же владелец переменной.
5. Откройте `Variables` у выбранного владельца, чтобы найти запись и её значение. Не удаляйте переменные чужих конфигураций ради проверки примера.

![](https://i.imgur.com/J9n7GkS.png)

На старом снимке показан просмотр переменных. В текущем редакторе также есть `Add variable...`, редактирование значения с `Save` и удаление через `Remove`. Для примера значение меняет сам скрипт; ручной ввод может изменить его тип.

## Выбрать время жизни данных

| Место хранения | Что сохраняется |
| --- | --- |
| Локальная переменная C# | Только до выхода из своего блока или метода. |
| Поле или свойство [песочницы](/ru/scripting/sandbox) | Между запусками одного её экземпляра; перекомпиляция или пересоздание экземпляра сбрасывает поля. |
| `Variables` текущего скриптового контекста | Запись у владельца, которая переживает перекомпиляцию кода. Другое действие с тем же именем переменной не обязательно использует этого владельца. |
| Переменная ауры или папки | Данные выбранного узла и наследование для дочерних узлов. Можно явно обратиться к общему владельцу из нескольких скриптов. |

Простые поддерживаемые значения входят в сохраняемую конфигурацию. Хранилище не делает любой произвольный .NET-объект пригодным для записи на диск; сохранение конфигурации и дескриптор переменной — разные вещи.

<details>
<summary>Локальная переменная, свойство и индексатор</summary>

Локальная переменная не решает задачу счётчика между запусками:

```csharp
var test = 123;
```

Свойство живёт дольше локальной переменной, но только в одном экземпляре песочницы. Этот отдельный пример каждый раз назначает `16`, а не увеличивает значение:

```csharp

int MyCounter { get; set; }

// здесь много-много вашего кода

MyCounter = 16;

// здесь еще больше кода

Log.Info($"Counter: {MyCounter}");

```

Число записей текущего контекста можно вывести так:

```csharp
Log.Info($"Variables count: {Variables.Count}");
```

Индексатор работает с `object`. Следующий фрагмент каждый раз перезаписывает значение единицей:

```csharp
Variables["myCounter"] = 1; // записываем 1 в переменную с именем myCounter
Log.Info($"Counter value: {Variables["myCounter"]}"); // считываем значение переменной myCounter, будет 1
```

Поэтому для арифметики требуется приведение типа. Этот самостоятельный фрагмент сначала пишет `1`, затем получает `2`:

```csharp
Variables["myCounter"] = 1; // записываем 1 в переменную с именем myCounter
// Variables["myCounter"] = Variables["myCounter"] + 1; // не сработает и выдаст ошибку!

Variables["myCounter"] = (int)Variables["myCounter"] + 1; // а вот это уже сработает
Log.Info($"Counter value: {Variables["myCounter"]}"); // в myCounter будет 2
```

Типизированный `Variables.Get<int>` из основного примера задаёт имя и тип один раз. Его `Value` читает и записывает хранилище; сам дескриптор не требует `Dispose`.

</details>

## Передать значение другой ауре

Создайте рядом со скриптом собственную ауру `Something`. Эти **альтернативные** фрагменты записывают `16` в её `myCounter`; они не продолжают увеличивать счётчик текущего скрипта.

По относительному пути:

```csharp
// Создайте рядом со скриптом ауру Something.
var auraVariable = Variables.Get<int>(@".\Something", "myCounter");
auraVariable.Value = 16;
```

Или через найденный узел:

```csharp
var aura = AuraTree.GetAuraByPath(@".\Something");
var auraVariable = Variables.Get<int>(aura, "myCounter");
auraVariable.Value = 16;
```

Путь разрешается относительно текущего контекста дерева. Одинаковое имя переменной не заменяет выбор владельца. Точные варианты вызовов — в [Variables API](/ru/scripting/api/IVariablesScriptingApi).

## Как работает наследование

Значение папки доступно её дочерним узлам. Локальная запись с тем же именем перекрывает унаследованную; после удаления локальной записи снова доступно значение предка. Это похоже на [наследование CSS](https://en.wikipedia.org/wiki/CSS): ближняя настройка имеет приоритет.

Так распространяются и значения по умолчанию: например, `default.WindowSelector.TargetWindow` влияет на выбор окна во вложенных аурах. Не меняйте такие служебные имена ради проверки счётчика.

Различия отсутствующей записи, `null`, значения по умолчанию и подписки разобраны в [типизированных операциях](/ru/scripting/api/scripting/variables). Законченный пример общего владельца, `Remove()` и повторного `Run` — в [руководстве по времени жизни](/ru/scripting/api/scripting/variable-lifecycle-operations).

Переменные дерева поведения (Blackboard) имеют свой контекст; этот пример их не создаёт и не описывает их настройку.
