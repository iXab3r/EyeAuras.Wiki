# Подготовить отчёт, который поможет воспроизвести проблему

Если действие не сработало или мини-приложение показало ошибку, сохраните отчёт этого запуска: описание шагов, логи и выбранные вложения. **Save…** создаёт файл на вашем диске, и вы можете посмотреть, что в него вошло, прежде чем отдавать автору набора. Отправляет отчёт отдельная кнопка **Send**.

## Сохранить архив для проверки

1. После проблемы откройте **Report a problem** в EyeAuras. Окно может открыться и само после исключения, или по кнопке в мини-приложении, если автор её добавил.
2. В комментарии напишите, что вы делали, что получилось и чего вы ждали. Например: «После выбора файла нажал Execute. Запись в журнале появилась, но результата нет. Ожидал, что откроется файл». Если автор заранее заполнил комментарий, его можно исправить или стереть.
3. Выберите логи нужного запуска. Если EyeAuras уже перезапускался, нужен и более ранний файл, в котором записана сама ошибка. Конфигурацию аур добавляйте, только если она относится к проблеме.
4. Просмотрите выбранные вложения, особенно снимки окон и конфигурацию. Нажмите **Save…**, выберите папку и дождитесь, пока архив `.7z` появится в Проводнике.

   ![В прежнем окне отчёта для локального архива выберите Save](/assets/callouts/batch2/ru/report-save-send.png)
5. Откройте архив и проверьте comment.txt и нужные логи. Файл на диске никуда не отправлен: ни поддержка, ни автор его ещё не получили.

**Save…** и **Send** используют один и тот же снимок диагностических данных. Если после открытия окна вы сменили аккаунт или подписки, снимок не обновится. Чтобы собрать новое состояние, откройте окно отчёта заново.

| Кнопка или состояние | Что происходит |
| --- | --- |
| Save… | Архив готовится и сохраняется на ваш диск. Потом открывается папка с ним. |
| Send | Архив готовится и загружается через настроенный обработчик. В обычном EyeAuras это сервер EyeAuras, а мини-приложение может задать свой. Кнопка доступна, только если обработчик есть. |
| Report sent / Report sent successfully | Обработчик вернул ID отчёта. Сохраните ID для обращения. |
| Copy | Копирует ID отправленного отчёта или текущий текст состояния. |
| Cancel | Закрывает окно. |

Если решили отправить отчёт в EyeAuras, нажмите **Send** и дождитесь подтверждения с ID. Сообщения **Compressing report…** и **Sending report…** — ещё не конец. Отчёт, отправленный в EyeAuras, не доставляется автоматически всем авторам из списка подписок. Если автор попросил файл напрямую, нужен сохранённый архив.

Если сбой появился после изменения настроек, сначала сохраните отчёт, а потом уже откатывайтесь через [историю конфигурации](/ru/features/config-rollback). Восстановление заменяет рабочую конфигурацию и перезапускает приложение.

## Что находится в архиве

| Файл | Содержимое и условия включения |
| --- | --- |
| comment.txt | Итоговый комментарий, если он не пустой. |
| systemInfo.txt | Доступные сведения о системе и процессе: ОС, имя пользователя Windows, компьютер, пути и командная строка. |
| applicationInfo.txt | Приложение, отправитель, лицензия, запуск, статистика дерева и подписки. Обязательный файл: текущий EyeAuras добавляет его всегда, какие бы логи и ауры вы ни выбрали. В старом отчёте его может не быть. |
| stacktrace.txt | Сведения об исключении, если оно есть. В отчёте, открытом вручную, исключения может не быть. |
| .log приложения | Выбранные логи. Недавние файлы обычно уже отмечены, более ранние можно выбрать отдельно. |
| EventLog_*.log, metrics.txt и другие диагностические файлы | Доступные приложению события Windows, показатели производительности и прочие сведения. |
| Wnd *.png / Screen *.png | Снимки окон приложения и рабочего стола. Доступные снимки окон выбраны по умолчанию, рабочего стола — нет. |
| Auras.zip и файлы конфигурации | Выбранные настройки и дерево аур. По умолчанию не отмечены. |

В командной строке, тексте запуска, логах, изображениях и выбранных аурах могут быть ваши локальные данные. Если снять флажок с конфигурации, сведения об аккаунте и подписках всё равно останутся в обязательном applicationInfo.txt.

## Информация о приложении

`applicationInfo.txt` содержит то, что было известно локально в момент подготовки отчёта. При сборе данных приложение не входит в аккаунт, не обновляет лицензию или подписки и не обращается к серверу.

| Ключи | Что означают |
| --- | --- |
| `CapturedAtUtc`, `App.*` | Время снимка, фактическое имя, версия и профиль приложения, готовность и время работы. |
| `User.Id`, `User.Name` | Отправитель из локального снимка активной лицензии. К владельцам шар эти данные не относятся. |
| `User.License.*` | Тип лицензии, валидность, доступные даты начала и окончания, названия возможностей. Ключа лицензии и полной подписанной лицензии здесь нет. |
| `Startup.CommandLine`, `Startup.Config` | Исходная командная строка процесса и текст `startup.cfg` выбранного профиля на момент сбора. Исходный текст сохраняется, даже если парсер запуска не смог его прочитать. |
| `Startup.Parsed.*` | Доступные фактические настройки запуска: режимы EyePad, окна и готовности, флаги безопасного режима и режима только чтения, параметры input/run/eval/compile/output. |
| `Tree.*` | Количество папок, аур, деревьев поведения и включённых элементов. Макросы считаются деревьями поведения. Самого дерева и списка имён здесь нет — для этого приложите конфигурацию аур. |
| `Subscriptions.Count`, `Subscriptions.N.*` | ID и путь папки, тип подписки, ID шары, доступные ревизия, название, владелец и URI, признак локального клона. Каждая подписка или клон — отдельная строка. |
| `UnavailableSections.*` | Разделы, которые собрать не удалось. Остальные данные сохраняются. |

Текст `startup.cfg` читается при подготовке отчёта и может отличаться от файла, с которым приложение запускалось.

### Формат и пример

Файл записан в UTF-8, каждая строка имеет вид `Key=Value`. Делите строку по **первому** `=`. Регистр ключей важен. Неизвестные ключи и пустые строки можно пропускать. Порядок ключей не гарантируется.

В значениях обратный слеш записывается как `\\`, возврат каретки — `\r`, новая строка — `\n`, табуляция — `\t`. Декодируйте один раз, слева направо, без повторных замен. Знаки равенства и кавычки — обычные символы. Булевы значения — `true`/`false`, числа не зависят от локали, даты записаны в ISO 8601 UTC.

`Version=1` соответствует `IPoeEyeConfigVersioned.Version` и меняется только при несовместимом изменении формата. Новый ключ эту версию не меняет. `App.Version` — версия самого приложения. Центральный обработчик сейчас поддерживает версию 1. Если контекста нет, он не читается или не поддерживается, основной отчёт всё равно обрабатывается, а исходный архив сохраняется.

Неизвестные значения пропускаются. Доступная пустая строка записывается как `Key=`, пустая коллекция — как `Prefix.Count=0`. У недоступной коллекции счётчика нет. Индексы коллекций начинаются с нуля.

Ниже сокращённый снимок с условными именами и ID:

```text
Version=1
CapturedAtUtc=2026-10-11T10:15:30.0000000Z
App.Name=DemoMiniApp
App.Version=1.9.10047.0
App.Profile=release
App.IsLoaded=true
App.UptimeSeconds=125
User.Id=8b8fae9e-1c40-4b37-bbc7-c9728c12db34
User.Name=Alice
User.License.Type=Standard
User.License.IsValid=true
User.License.Features.Count=2
User.License.Features.0=EyeAuras.DefaultAuras
User.License.Features.1=EyeAuras.Social
Startup.CommandLine=DemoMiniApp.exe --profile release
Startup.Config={"CommandLine":"--profile release"}\r\n
Startup.Parsed.IsEyePad=true
Tree.TotalItems=7
Tree.Folders=3
Tree.Auras=3
Tree.BehaviorTrees=1
Tree.EnabledItems=6
Subscriptions.Count=2
Subscriptions.0.FolderPath=DemoMiniApp
Subscriptions.0.SubscriptionType=ShareAuraSubscriptionConfig
Subscriptions.0.ShareId=demo-share-one
Subscriptions.0.Revision=12
Subscriptions.0.OwnerUserName=AuthorOne
Subscriptions.0.IsLocalClone=false
Subscriptions.1.FolderPath=Helpers
Subscriptions.1.SubscriptionType=ShareAuraSubscriptionConfig
Subscriptions.1.ShareId=demo-share-two
Subscriptions.1.OwnerUserName=AuthorTwo
Subscriptions.1.IsLocalClone=true
UnavailableSections.Count=0
```

## Как автору шары принимать архивы

Попросите пользователя сохранить отчёт и прислать исходный архив с коротким описанием, как воспроизвести проблему.

Имя по умолчанию выглядит как `AppName_version_profile_reportId.7z`, например:

```text
DemoMiniApp_1.9.10047.0_release_0123456789abcdef0123456789abcdef.7z
```

В имени приложения могут быть подчёркивания. Когда регистрируете обращение, сохраняйте исходное имя файла и ID отчёта. Сервер EyeAuras распознаёт и `.zip` с той же схемой имени.

1. Прочитайте `comment.txt` и `stacktrace.txt`, если он есть, чтобы понять проблему и исключение.
2. Откройте `applicationInfo.txt` и проверьте приложение, версию, профиль, отправителя, параметры запуска и нужную ревизию шары. Если шар или клонов несколько, смотрите весь список подписок.
3. Сопоставьте проблему с логами того запуска. Если данных мало, попросите архив с более ранними логами или с конфигурацией аур.
4. Сохраните оригинальный архив рядом с обращением. В сформированном описании длинный текст запуска может быть сокращён, а полный файл остаётся в архиве.

Если `applicationInfo.txt` нет, используйте комментарий, сведения о системе и логи. Если сведений о пользователе, шаре или лицензии нет, не заполняйте их догадками.

## Что записывает центральный обработчик

Для отчётов EyeAuras обработчик сначала берёт непустой `User.Name`. Прежний поиск имени в сведениях о системе и логах остаётся запасным вариантом. Если данные есть, в YouTrack заполняются строковые поля:

| Поле | Источник |
| --- | --- |
| `External Id` | ID отчёта из имени архива. По нему ищутся дубли в целевом проекте. |
| `External UserName` | Имя отправителя, с прежним запасным способом извлечения. |
| `External AppName` | `App.Name`. |
| `External UserId` | `User.Id`. |
| `External ShareId` | Первая подписка с непустым `ShareId` в порядке файла. |
| `External OwnerUserName` | Канонический владелец первой шары и её ревизии на сервере, если его удалось определить. |

Все подписки и клоны остаются в описании и исходном файле. Индексируется только первая шара. Следующие не подставляются ни вместо неё, ни вместо её владельца. `OwnerUserName` из клиентского файла — локальная подсказка, а не каноническое имя с сервера. Если ревизия не указана, берётся активная серверная. Если ревизия указана явно, но недоступна, активная вместо неё не берётся.

Лицензия, возможности, статистика дерева и параметры запуска попадают в описание, а не в отдельные поисковые поля. Исходный архив прикладывается к задаче. Отчёт опознаётся по точному ID, в каком бы состоянии ни была задача. После включения доставки мини-приложений поиск идёт по EA и MAPS. POE обрабатывается отдельно.

Обычные отчёты EyeAuras попадают в EA. У PoEBane остаётся свой обработчик и свой целевой проект, по умолчанию POE. Если его импорт отключён, архивы `PoEBane_` пропускаются. API, через который авторы смогут получать отчёты, планируется. Принимать сохранённые архивы вручную можно уже сейчас.

## Отчёты мини-приложений в YouTrack

После включения центральной доставки новые отчёты мини-приложений попадают в **EyeAuras MiniApps (MAPS)**. Старые отчёты идут прежним маршрутом. Если доставку приостановить, новые архивы остаются в очереди и в EA не отправляются.

Для первой непустой ShareId сервер определяет сведения о шаре и создаёт или переиспользует группу `reports-share-ShareId`. Группа общая для всех ревизий этой шары. Отчёт видят внутренняя поддержка и эта группа. Если первой шары нет или определить её не удалось, отчёт остаётся внутренним. Следующая шара для выдачи доступа не подставляется.

Автора и его команду в нужную группу добавляет администратор YouTrack. Имена пользователя и владельца из отчёта никого не добавляют автоматически. Участники группы могут работать с доступными отчётами, комментариями, состояниями и вложениями. Поля, которые заполнил обработчик (отчёт, отправитель, шара), проект и видимость может менять внутренняя поддержка. Помеченные ответы могут отправляться отправителю отчёта. Закрытые внутренние заметки не пересылаются.

Доступ даётся ко всему отчёту: к исходному архиву, сведениям о лицензии, другим подпискам и приложенной конфигурации.

После включения обработчик узнаёт один и тот же отчёт и в EA, и в MAPS. Если задачу закрыли или незавершённый импорт перезапустили, новая задача не создаётся. По сохранённой записи импорта можно дозагрузить вложения в уже опубликованную задачу.
