# Активировать доступ к нужному Pack

Сублицензия — это ключ доступа к одному набору (Pack) или мини-приложению автора. Ключ от автора привязывается к вашему аккаунту: срок виден в профиле, а Pack можно запускать.

Вам нужны ключ от автора продукта, аккаунт EyeAuras и связь с сервером. Сначала сверьте название набора: ключ от одного Pack не открывает остальные.

1. Войдите в аккаунт и откройте [My Account](https://eyeauras.net/my). Введите неактивированный ключ в **License key** и нажмите **Activate key**.
2. Дождитесь сообщения **License key activated.** и обновлённого списка лицензий.
3. Найдите Pack в списке, проверьте срок и состояние. В приложении это видно в профиле и на временной шкале доступа к наборам.
4. Запустите Pack по инструкции автора.
5. Если доступ ожидает выдачи, истёк, заморожен или занят другими сессиями, прочитайте состояние и сообщение продукта. Повторная активация того же ключа не продлевает срок и не снимает привязку к компьютеру.

Войти без заранее созданного аккаунта можно [по ключу](/ru/features/keylogin): в текущем окне это **Sign in with key → Login with key**.

## Читать условия и состояние доступа

| Условие или состояние | Что оно означает |
| --- | --- |
| Calendar time | Срок идёт непрерывно с момента активации, даже когда приложение закрыто. |
| Consumed time | Время тратится, пока активна аренда сессии. |
| Максимум сессий | Сколько логических слотов доступно. Что считать сессией — запуск, окно, ресурс или другое действие — решает автор продукта. |
| Hardware binding | Слоты привязаны к ПК. Смена аккаунта или повторный ввод ключа не заменяют освобождение привязки. |
| Ожидание выдачи | Запрос доступа создан, но разрешения ещё нет. |
| Выданный доступ | Текущая аренда разрешена. |
| Истечение / отказ / освобождение | Три разные причины, по которым доступа сейчас нет. Смотрите на сообщение. |

![Лицензии наборов и временная шкала](https://s3.eyeauras.net/media/2026/03/EyeAuras_vKT0Nhnf8z.png)

Заморозка пользователем и заморозка автором — разные операции. Что вам доступно и сколько изменений осталось, зависит от условий конкретной лицензии. В текущей шкале смену режима или заморозку сначала готовят, а потом применяют кнопкой **Apply**. Кнопка отвязки ПК есть только там, где отвязка разрешена. Если список показывает уже выданные подписанные разрешения без управляющих данных, этих кнопок может не быть.

Авторская **Freeze consumed time** приостанавливает расход в режиме Consumed time. По вопросам о конкретном ключе пишите автору, который его выдал.

## Автору: задать условия новых ключей

Нужна своя публикация и право ей управлять. На странице Pack откройте **License settings → Edit**, выберите условия и сохраните. После сохранения проверьте сводку.

![Настройки лицензирования на странице набора](https://s3.eyeauras.net/media/2026/03/msedge_kjbwxZPnYk.png)

| Настройка | Как влияет на лицензии |
| --- | --- |
| Time accounting | Calendar time или Consumed time для новых ключей. |
| Hardware binding | Требовать привязку к ПК или разрешить работу без неё по условиям слотов. |
| Product features for new keys | Возможности продукта, которые копируются в новый ключ. В этой форме их можно только посмотреть, управляют ими отдельно через лицензионный механизм. |
| Freeze consumed time | Переключатель, который сейчас приостанавливает расход Consumed time. |
| Issued licenses | Выданные ключи и их состояния. |
| Active leases | Текущие лицензионные сессии и их техническое состояние. |

Режим учёта, привязка и возможности копируются в ключ в момент его создания. Если поменять политику позже, у уже выпущенных ключей условия останутся прежними. Живая заморозка — отдельный случай.

В текущей веб-форме **License Issue** выпускать ключи может администратор. Обычному автору, чтобы выпустить партию, нужно договориться через [контакты](/contacts). В форме задаются количество, **Duration**, комментарий и допустимые переопределения режима, привязки и числа сессий. Сами ключи — секреты, в публичное описание Pack они не входят.

<summary>Подключить проверку к своему набору или мини-приложению</summary>

Обычному Pack хватит стандартного профиля EyeAuras. Для своего интерфейса есть готовый элемент Blazor:

```razor
<LoginWidget/>
```

Он открывает штатный вход в Blazor-окне EyeAuras, которое его поддерживает. В своём ImGui/WPF/Blazor-интерфейсе можно вызывать операции IEyeHubService. Ниже — варианты для обработчиков формы, выполнять их все подряд не нужно. Значения берите из своей формы, а не из ключей, сохранённых в коде.

```csharp
var eyeHub = GetService<IEyeHubService>();

var userLicense = await eyeHub.PerformLogin(username, password);
var keyLicense = await eyeHub.LoginWithLicenseKey(licenseKey); // key login
var updatedLicense = await eyeHub.ActivateLicenseKey(extraLicenseKey); // only for already logged-in user

Log.Info($"Current user: {eyeHub.ActiveLicense.Username}");
Log.Info($"Connection state: {eyeHub.ConnectionState}");
```

В текущем клиенте вход по ключу — **LoginWithLicenseKey**. ActivateLicenseKey вызывают после входа, чтобы привязать дополнительный ключ.

Состояние профиля читается через ILicenseAccessor. Примеры ниже — фрагменты работающего скрипта EyeAuras, где сервисы выдаёт host. Обычному C#-классу зависимости передают отдельно. Эти поля нужны для диагностики: по ним нельзя решать, есть ли доступ сейчас.

```csharp
var license = GetService<ILicenseAccessor>();

Log.Info($"Username: {license.Username}");
Log.Info($"UserId: {license.UserId}");
Log.Info($"HardwareId: {license.HardwareId}");
Log.Info($"AppVersion: {license.AppVersion}");
Log.Info($"StartsAt: {license.StartsAt}");
Log.Info($"Roles: {string.Join(", ", license.Roles)}");
```

Свои данные лучше связывать со стабильным UserId, а не с именем пользователя. Если у вас уже есть IEyeHubService, UserId доступен в принятом снимке лицензии:

```csharp
var eyeHub = GetService<IEyeHubService>();
var userId = eyeHub.ActiveLicense.UserId;

Log.Info($"Current user id: {userId}");
```

Отдельный атрибут можно прочитать, не выводя всю подписанную лицензию:

```csharp
var license = GetService<ILicenseAccessor>();
var userId = license.GetAttribute("UserId");
```

MaximumSessions и срок из ShareSublicenses удобно показывать пользователю:

```csharp
var license = GetService<ILicenseAccessor>();

foreach (var sublicense in license.ShareSublicenses)
{
    Log.Info($"ShareId: {sublicense.ShareId}");
    Log.Info($"MaximumSessions: {sublicense.MaximumSessions}");
    Log.Info($"ExpiresAt: {sublicense.ExpiresAt}");
}
```

### Запрашивать и удерживать сессию

В клиентах до build 9298 включительно работал совместимый пассивный путь. В новых клиентах Pack должен сам запросить сессию через ISublicenseManager. Если только читать ShareSublicenses, активированный ключ может быть виден в профиле, но нужную аренду никто не запросит.

Первый пример целиком выполняется в **Script.csx работающего EyeAuras**. Замените ShareId на идентификатор своего набора. Скрипт следит за состоянием до **Stop**, но логику продукта не запускает и не блокирует. Всё ожидание лежит внутри using-блока. При выходе из него сначала освобождается подписка, потом аренда, даже если сам Run после этого продолжится. Для своей защищённой работы поставьте вместо ожидания свой код в том же блоке и отдельно учитывайте IsGranted и потерю доступа.

```csharp
using System;
using System.Reactive.Linq;
using System.Threading;
using System.Threading.Tasks;
using EyeAuras.Loader.Shared.Api;
using EyeAuras.Shared.Sharing;

{
    using var lease = GetService<ISublicenseManager>()
        .Rent(new AuraShareId("S20260209165639iiQZB0NCruAb"));
    using var observer = lease.WhenChanged()
        .Subscribe(x => Log.Info($"Lease: {x.IsGranted} / {x.Status} / {x.Message}"));

    // Место ожидаемой работы с арендой. Здесь только наблюдаем до Stop.
    await Task.Delay(Timeout.Infinite, cancellationToken);
}
```

Stop отменяет ожидание. using закрывает оба объекта и при отмене, и при исключении. Ниже другой справочный вариант: аренда живёт до конца Run, а наблюдатель привязан к ExecutionAnchors. Сам фрагмент Run не удерживает, после него должна продолжаться ваша работа:

```csharp
var lease = GetService<ISublicenseManager>()
    .Rent(new AuraShareId("S20260209165639iiQZB0NCruAb"));

lease.WhenChanged()
    .Subscribe(x =>
    {
        if (!x.IsGranted)
        {
            Log.Warn($"Sublicense is not granted yet: {x.Status} / {x.Message}");
            return;
        }

        Log.Info("Sublicense granted, pack can continue working");
    })
    .AddTo(ExecutionAnchors);
```

| Операция | Граница её результата |
| --- | --- |
| Rent | Сразу создаёт одну логическую сессию и запускает фоновую синхронизацию. Это ещё не значит, что доступ выдан. |
| IsGranted | Защищённую работу разрешает только текущее положительное значение. |
| WhenChanged | Сообщает текущее состояние и следующие изменения. При потере доступа остановите или приостановите зависимую работу. |
| Dispose / выход из using-блока / конец Run | Локально завершает использование сессии. Это не подтверждает, что сервер сразу освободил слот. |
| Несколько Rent | Несколько отдельных сессий, а не повторная проверка одного объекта. |

Саму аренду EyeAuras привязывает к текущему Run, а AddTo(ExecutionAnchors) выше управляет вашей подпиской. Локальный объект нельзя сохранять после завершения как разрешение для следующего запуска. Полный контракт и контекст — в [руководстве по входу и лицензированию](/scripting/api/core/login-and-licensing).

Если связь ненадолго пропала, уже выданный доступ может восстановиться из подписанного кэша, пока тот действует, в том числе после сбоя. Это не полный автономный режим: без подходящего разрешения новый доступ может ждать сервера. После сбоя сервер какое-то время может считать прежнюю сессию занятой.

### Передать состояние остальным аурам

В обычном наборе автор может передавать разрешение в отдельную ауру IsAuthenticated с Fixed Value или в переменную. Остальная логика смотрит на это состояние через [условия включения](/ru/features/enabling-conditions), [поиск ауры](/ru/scripting/examples/basic/find-aura) или [переменные](/ru/scripting/variables). Значение должно повторять текущий IsGranted, включая потерю доступа.

Для отдельного интерфейса подойдёт [мини-приложение, как в примере](https://eyeauras.net/share/S20251105201607zPUUkZryl4CY).

| Подготовка распространения | Что она даёт |
| --- | --- |
| Packed Only | Обычный получатель получает подготовленный вариант. |
| Binaries Only | Распространяется собранный код вместо исходного текста. |
| Performance-first / Security-first | Дополнительная обработка бинарного кода, если она доступна для вашей сборки. |
| Private Content | Просмотр в интерфейсе папки ограничен. |

Подробнее — [Паки](/ru/features/packs), [защита скриптов](/ru/features/script-protection) и [права папки](/ru/features/permission-model).
